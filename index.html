U.S. Quant Recruiting Playbook

从零开始的Quant Recruiting Guide

把“学什么、做到什么程度、什么时候开始投、面试怎么准备”放进同一张地图。它不是速成承诺，而是一套能反复执行、复盘和迭代的美国量化入门框架。

进入完整 SOP先选方向
THE WHOLE SYSTEM
  1. 01选对目标岗位QR / QT / QD，要求不一样
  2. 02搭建底层能力概率、统计、编程与市场直觉
  3. 03做出可讲项目从结论到假设、验证与复盘
  4. 04进入招聘系统简历、投递、笔试、面试、选择
Before everything

先改掉三个
常见误区

大多数人卡住，不是因为题做得不够多，而是顺序错了：没选岗位就堆知识；没定义标准就做项目；等“准备完”才开始 recruiting。

01

量化不是一个岗位

研究、交易、开发的筛选信号不同。先明确目标，再决定数学深度、代码重心和项目形态。

02

项目不是作品展示

真正被评估的是你的研究过程：问题怎么定义，偏差怎么发现，结果为什么可信，失败后怎么改。

03

Recruiting 是并行系统

信息、简历、投递和 mock 不应等到最后。学习与求职要同时推进，反馈才会更快进入下一轮训练。

01 / Pick your lane

先选赛道，
再配能力

如果还不确定，可以同时探索，但简历与面试准备必须有主线。点击岗位，查看最核心的筛选信号。

Quant Researcher · 研究

围绕数据提出假设、设计验证、构建模型，并把研究结论转化为可执行的交易信号。

  • 概率统计与推断：分布、估计、假设检验、回归、时间序列
  • 研究能力：实验设计、数据泄漏、过拟合、稳健性与解释
  • 代码：Python 数据栈、向量化、清晰可复现的 research pipeline
Hiring signal

比“模型复杂”更重要

能否把模糊问题拆成可检验假设；能否发现数据与评估中的陷阱；能否清楚解释结果为何成立。

更适合：喜欢研究、数据、建模，愿意长时间追问“这个结论是真的吗？”

Quant Trader · 交易

在不完整信息和时间压力下做判断，理解风险收益，并持续优化执行与策略。

  • 概率与心算：条件概率、期望、博弈、快速估算
  • 决策：赔率、仓位、信息更新、压力下的稳定表达
  • 市场直觉：做市、价差、库存风险、流动性与 adverse selection
Hiring signal

速度之外还有校准

不是单纯“算得快”，而是能在新信息出现时调整判断，知道什么时候激进、什么时候保守。

更适合：喜欢竞技、即时反馈、博弈和高密度决策，对数字敏感且情绪稳定。

Quant Developer · 工程

让研究和交易系统可靠地运行：数据、回测、执行、性能、基础设施与工具链。

  • 计算机基础：数据结构、算法、操作系统、网络、并发
  • 工程质量：测试、可观测性、故障边界、性能分析
  • 语言：C++/Python 为主，理解内存、延迟与生产系统取舍
Hiring signal

正确、清晰、可扩展

面试官关心你能否写对代码、分析复杂度、解释系统权衡，并把模糊需求变成可靠实现。

更适合：享受搭系统、排查问题、优化性能，希望离交易场景很近但以工程为主。

Recommended starting point

QR 探索线 · 先做基线诊断

你对研究型任务更有兴趣，且数学基础可以成为早期优势。先验证自己是否享受完整研究闭环，再决定是否继续加深。

  1. 做一次概率与 Python 基线测试
  2. 复现一个公开数据上的简单 baseline
  3. 写一页研究 memo：假设、方法、结果、局限
02 / The SOP

一套可执行的
五阶段路线

不按固定周数推进，而按“出口标准”推进。每一阶段都必须留下可验证的产出，才能进入下一阶段。点击每一阶段展开。

01

定位与基线诊断

把模糊的“想做量化”变成明确目标。

出口：目标清单

要做什么

列出 QR / QT / QD 的岗位差异；按背景、兴趣、优势选 1 个主线与 1 个备选。

交付物

20–30 家公司池、目标岗位 JD 关键词表、数学/代码/经历三项基线评分。

不要做

一上来刷几百题；只盯头部公司；因为专业不“对口”就自我筛掉。

02

底层能力搭建

以面试和项目会真实调用的知识为边界。

出口：能解释 + 能使用

数学

概率、随机变量、条件期望、统计推断、线性代数；QR 再深入回归与时间序列。

编程

Python 熟练度、数据结构与算法；QD 增加 C++、并发、系统与性能。

训练方式

每个概念完成“定义 → 直觉 → 推导 → 代码 → 反例”，避免只看课不输出。

03

项目与叙事闭环

做一个小而完整、经得住追问的项目。

出口：5 分钟讲清

问题设计

从一个明确问题开始：预测什么、为何有意义、什么算成功、基线是什么。

可信验证

时间切分、交易成本、泄漏检查、敏感性分析、失败案例与稳健性测试。

表达结构

Context → Hypothesis → Method → Result → Failure → Next step，准备 30 秒和 5 分钟版本。

04

Recruiting 资产上线

让市场尽早给你的准备方向反馈。

出口：可投递

简历

一页，先写结果和证据，再写方法；每个 bullet 都能被深挖十分钟。

投递系统

按公司、岗位、时间、状态、联系人、下一步维护 tracker；分批投递并复盘转化率。

Networking

以具体问题开启对话，目标是获得信息校准，不是向陌生人直接索要 referral。

05

面试冲刺与复盘

把知识训练成压力下可调用的表现。

出口：稳定通过

题型训练

概率、brain teaser、coding、market making、research case 按岗位配比，不平均用力。

Mock

至少覆盖技术、项目深挖和行为面；录音复盘表达、停顿、假设和自我纠错。

错题闭环

记录题目背后的能力缺口，24 小时内重做，7 天后无提示复测。

03 / Skill stack

能力栈，具体
学到什么程度

“学过”不算掌握。以下每一层都用可观察的行为定义完成度：能推、能写、能解释、能在新题里迁移。

A / PROBABILITY

概率与统计

所有岗位共通的语言。重点不是背公式，而是把不确定性变成可计算的决策。

  • 条件概率、Bayes、期望、方差、常见分布
  • 组合计数、随机过程直觉、估计与检验
  • 能口述假设，写出推导，并做 sanity check
B / PROGRAMMING

编程与算法

先保证正确与清晰，再追求速度。面试代码要能边写边讲，项目代码要可复现。

  • Python：数据处理、模拟、测试、性能意识
  • DSA：数组、哈希、树、图、动态规划基础
  • QD：C++、内存、并发、网络与系统设计
C / RESEARCH

研究与数据

优秀项目的核心不是高收益曲线，而是研究流程中对偏差和失败的控制。

  • 明确基线、指标与样本外评估
  • 避免 look-ahead、survivorship 和 data snooping
  • 加入成本、容量、稳定性和 regime 分析
D / MARKET SENSE

市场与交易直觉

不需要先成为金融专家，但要理解价格、风险、流动性与参与者行为如何连接。

  • 收益、波动率、相关性、风险调整后收益
  • 订单簿、点差、做市、库存风险与执行
  • 能把模型输出翻译成交易约束

05 / Questions

常见问题，
直接回答

这条路没有唯一背景模板，但有相对稳定的评估逻辑：学习速度、问题拆解、数理基础、代码质量和清晰表达。

非名校 / 非数学专业，还有机会吗？

有，但需要更主动地建立“可验证信号”：高质量课程成绩、竞赛或科研、扎实项目、强代码表现、相关实习，以及能帮助你通过筛选的有效连接。不要用背景否定自己，也不要忽略筛选现实。

要不要先学完整的金融知识？

通常不需要。先掌握收益、风险、市场微观结构和衍生品的基本直觉，再根据目标岗位加深。多数入门准备的瓶颈仍然是概率、统计、编程和问题求解。

项目一定要做量化策略吗？

不一定。一个扎实的预测、优化、实验或系统项目，只要体现了清晰假设、严谨验证和真实取舍，同样可以成为强信号。关键是岗位相关性与叙事质量。

什么时候开始投递？

不要等到“全部准备完”。当简历没有明显硬伤、基础题能稳定完成、项目能讲清时，就可以分批开始。具体开放时间每年会变，应以公司官方 careers 页面为准。

刷题数量越多越好吗？

不是。更好的指标是：同类题能否识别结构、是否能在限制时间内表达思路、错题是否真正闭环。盲目追数量会掩盖能力缺口。

A tested framework

不靠速成，靠一套能持续复利的方法。

我也在用这套路径陪 mentee 从定位、搭框架、做项目到准备 recruiting。每个人的背景和节奏不同，但判断标准可以清楚、训练过程可以复盘、下一步可以具体。
